# ReelDeck v0.4.1

修复 v0.4.0 中恢复播放进度时一直显示加载圈的问题，并提前解码下一条视频，减少滑动后的等待。本次覆盖发布还修复首次滚动重复当前视频、没有上一条时错误离场，以及切换时旧画面闪回。构建号从 5 增至 6。

## 播放修复

恢复精确定位，避免长关键帧间隔视频停在更早的位置，导致画面交接超时。初始化、打开文件与画面就绪使用同一份 12 秒预算；超时后保留当前项并显示重试入口，不再遍历整个目录。

软解继续通过 GPU 显示。解码模式更改会保留播放位置与暂停状态，设置即时生效。恢复容器默认探测参数，关闭磁盘缓存，软解线程数限制在 2 至 4。

## 滑动与预加载

保留当前与备用两个播放器。当前视频开始播放就准备下一条的首帧，不等待会话写盘；滑到正在预加载的目标时接管同一任务，避免再次打开文件。预加载、交接和释放串行执行，旧请求不能覆盖当前播放的文件。

Android 前台硬解，后台软解准备下一条。交接先释放旧硬解会话，再让下一条接管前台硬解。桌面直接交接已准备的备用播放器。队列在最后一条播放期间确定下一轮顺序，让跨轮滑动也能复用预加载结果。

下方放下一条，上方放上一条；拖动时向上拉出下方视频，向下拉回上方视频，滚轮向下前进、向上返回。没有上一条时只回弹，不重新打开当前视频；触控板小幅滚动会累积触发，反向滚动可以立即返回。跨过循环边界后仍可回到刚播放的末项，再次向前时保留原来的顺序。

离场后把旧画面留在屏幕外，等新播放器就绪后再归位，避免等待期间闪回旧画面。打开期间忽略旧视频的播放结束事件，防止额外跳过目标。

## 本地验证

84 项 Flutter 测试、5 项打包脚本测试与静态分析通过。macOS 原生 release 验证覆盖 H.264、4K H.264、4K HEVC、非关键帧进度恢复、播放器交接、软解与 Feed 连续切换。四次已完成预加载的交接实测为 0 至 3 ms，没有加载圈；原有滑动动画仍为 180 ms。合成纯色样本用于验证状态与解码路径，不代表真实视频的性能增幅。

macOS 实际 Feed 的渲染截图检查通过滚轮和触控板事件覆盖首页回弹、红→绿、绿→红、红→绿、绿→蓝与跨轮返回，采样中没有出现旧帧闪回。

macOS release 构建、ARM64 包架构与签名检查通过，Android ARM64 与 ARMv7 release APK 构建及 ABI 检查通过。Android、Windows、Linux 真机播放与复杂视频性能仍待验收。本次按要求覆盖 v0.4.1 标签并重新构建全部平台安装包，不监控 GitHub CI；远程构建与附件替换结果尚未验证。

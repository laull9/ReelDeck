# ReelDeck v0.4.1

修复 v0.4.0 中恢复播放进度时一直显示加载圈的问题，并提前解码下一条视频，减少滑动后的等待。

## 播放修复

恢复精确定位，避免长关键帧间隔视频停在更早的位置，导致画面交接超时。初始化、打开文件与画面就绪使用同一份 12 秒预算；超时后保留当前项并显示重试入口，不再遍历整个目录。

软解继续通过 GPU 显示。解码模式更改会保留播放位置与暂停状态，设置即时生效。恢复容器默认探测参数，关闭磁盘缓存，软解线程数限制在 2 至 4。

## 滑动与预加载

保留当前与备用两个播放器。当前视频开始播放就准备下一条的首帧，不等待会话写盘；滑到正在预加载的目标时接管同一任务，避免再次打开文件。预加载、交接和释放串行执行，旧请求不能覆盖当前播放的文件。

Android 前台硬解，后台软解准备下一条。交接先释放旧硬解会话，再让下一条接管前台硬解。桌面直接交接已准备的备用播放器。队列在最后一条播放期间确定下一轮顺序，让跨轮滑动也能复用预加载结果。

## 本地验证

74 项 Flutter 测试、5 项打包脚本测试与静态分析通过。macOS 原生 release 验证覆盖 H.264、4K H.264、4K HEVC、非关键帧进度恢复、播放器交接、软解与 Feed 连续切换。四次已完成预加载的交接实测为 0 至 3 ms，没有加载圈；原有滑动动画仍为 180 ms。合成纯色样本用于验证状态与解码路径，不代表真实视频的性能增幅。

macOS release 构建、ARM64 包架构与签名检查通过，Android ARM64 与 ARMv7 release APK 构建及 ABI 检查通过。Android、Windows、Linux 真机播放与复杂视频性能仍待验收。本次只推送版本提交与标签，按要求不监控 GitHub CI；远程构建和 Release 产物尚未验证。

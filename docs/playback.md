# 播放与进度维护

Android 的播放器池只创建一个播放器。切换时先暂停并卸载当前文件，再打开目标文件，避免两个视频同时占用 MediaCodec。桌面仍使用两个播放器，下一条在暂停状态下预加载。Android 使用播放库的安全硬解选择和 GPU 输出，保留模拟器与不支持编码的软件回退，单播放器前向缓存上限 8 MiB。

`media_kit_video` 固定为 2.0.1。旧版 1.3.1 的 Android Surface 重建会跳到零位置；2.0.1 保留当前位置，并修复新 Flutter 的兼容问题。打开流程仍等待 AndroidVideoController 的 Surface 锁，再恢复目标位置。这里引用了包内实现；升级依赖时必须重新核对 `widListener`、锁和 Surface 初始化顺序。

启动等待初始化时也挂载 Feed，让原生 Texture 能接收首帧，避免初始化与首帧等待互相阻塞。Feed 的视频视图按播放器身份保留。每个播放器只挂一个 Video，IndexedStack 改变可见项，切换不复用其他播放器的订阅。加载期间显示黑色遮罩，文件参数、Surface、seek 和 `vo-configured` 就绪后撤去遮罩。画面等待有超时，失败进入现有跳过和重试流程。应用统一管理后台暂停与屏幕常亮，隐藏播放器不改变常亮状态。

滑动时让旧视频沿手势方向离场，再打开下一条。播放页沿用原有的黑色遮罩和加载提示；新视频就绪后从零偏移显示，后台预加载不阻挡画面。打开期间忽略重复滑动。切换回调包含后台预加载，回调完成后再播放入场动画会让已经显示的新视频突然移动，因此切换完成后不再添加位移动画。播放器组件始终挂载，切换不会重建 Surface。位置事件每 200 ms 至多刷新一次界面；进度写入每五秒采样，暂停、切换、后台、跳转完成和关闭时立即补存。

进度默认开启，缺少字段的旧设置使用开启值，用户明确保存的关闭值仍保留。打开视频时直接传入 `Media.start`，预加载也使用已保存位置。进度写入捕获媒体 ID 和位置，并单独串行执行；收藏、隐藏与播放次数使用只更新对应字段的 SQL，避免并发覆盖进度。播放完毕清零；超出视频时长的旧进度从头播放。状态表按媒体 ID 保留一条记录，重扫删除和目录移除仍清理对应记录，不产生采样历史表。

验证使用 `flutter analyze`、`flutter test` 和 Android release 构建。模拟器可检查 SAF、切换、恢复、错误和后台流程，但软件解码的 CPU 数据不能代替手机验收。真机应覆盖 H.264、HEVC、不同分辨率、快速切换、长时间连续播放、进度拖动和后台恢复，记录实际硬解路径、CPU、丢帧和内存变化。

本次 Android release 构建使用已有的 NDK 27.1.12297006；Flutter 默认要求的 28.2.13676358 目录缺少 source.properties，未改动项目默认版本。本机 API 37 模拟器在 host 和 SwiftShader 后端均报 EGL_BAD_ATTRIBUTE，播放进入超时恢复，原生画面与 CPU 验收没有通过。上游记录了[相同的模拟器 EGL 故障](https://github.com/media-kit/media-kit/issues/1343)，仍需 Android 真机完成上述验收。

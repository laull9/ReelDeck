# 播放与进度维护

打开视频保持精确定位：`hr-seek=yes`，恢复位置直接传入 `Media.start`。v0.4.0 曾关闭精确定位，却继续等待目标位置附近的画面；长 GOP 视频实际停在更早的关键帧，12 秒后超时，再遍历其他视频。macOS 已复现：请求第 7 秒，实际 `time-pos=0`，`vo-configured=yes`，VideoToolbox 正常工作。恢复精确定位后，同一样本从第 7 秒正常播放。

初始化、加载参数、Android Surface 锁和画面交接共享打开操作的 12 秒预算。原生属性查询也有超时。解码超时保留当前视频，结束加载提示，显示重试与跳过入口；不把整个目录逐项试完才显示错误。无法访问或损坏的文件仍按原有规则跳过。

启用预加载时保留当前和备用两个播放器。Android 前台使用硬解，后台备用实例用软解准备下一条的首帧；交接先释放旧视频的硬解会话，再将新前台切到用户选择的解码模式，避免同时争抢两个 MediaCodec。硬解使用播放库默认配置，保留模拟器检测与不支持编码的软解回退。桌面也使用两个播放器，仅预加载下一条；如果备用播放器仍保存上一条的对应位置，返回时可以复用，否则重新打开。预加载、交接与释放串行执行，请求捕获播放器身份，交接后的旧请求不能覆盖正在播放的文件。当前视频开始播放就启动下一条预加载，不等待会话写盘。滑到正在预加载的目标时接管同一任务，不取消后重新打开。循环队列在最后一条播放时确定下一轮顺序，预加载目标与实际首项保持一致。下一轮计划最多保留一份队列副本，返回后保留原顺序，重扫、重建队列或手动洗牌会使其失效，不新增数据库记录。切换到其他目标和关闭使尚未开始的旧预加载失效。关闭预加载释放备用媒体；此设置关闭时，切换仍需打开目标文件。

硬解与显示分别控制。选择纯软解只设置 `hwdec=no`，GPU 继续显示视频；更改解码模式会按保存位置重新打开当前视频，并保留暂停状态。软解线程数限制为 2 至 4，避免多个播放器分别创建大量解码线程。保留容器默认探测参数，不压缩 probe 时间来换启动速度。缓存放在内存中，不重复写磁盘；外置盘优化启用时前向缓存 8 MiB，反向缓存为零，关闭后分别为 32 MiB 和 8 MiB。

`media_kit_video` 固定为 2.0.1。Android 恢复位置等待 Surface 重建锁后执行，避免库内部恢复操作覆盖目标位置。这里引用包内实现；升级依赖时重新核对 `widListener`、锁和 Surface 初始化顺序。

启动等待初始化时也挂载 Feed，让 Texture 接收首帧。每个播放器只挂一个 Video，IndexedStack 改变可见项。加载期间显示黑色遮罩，文件参数、Surface、seek 和 `vo-configured` 就绪后撤去遮罩。应用统一管理后台暂停与屏幕常亮。

位置事件每 200 ms 至多刷新一次界面；进度每五秒采样，暂停、切换、后台、跳转完成和关闭时立即补存。写入捕获媒体 ID 与位置，收藏、隐藏和播放次数只更新对应字段。播放完毕清零，过期进度从头播放。状态表每条媒体只保留一份进度，重扫删除和目录移除清理对应记录。

## 损坏与高解码压力视频

滑到仍在预加载的目标时，等待期间显示加载提示，不再停在离场后的黑底上。预加载已确认文件损坏（打开报错）时直接记录错误并跳过；预加载超时可能只是后台软解太慢，前台按选定解码模式再打开一次。

播放中进度连续 10 秒不前进，视为损坏帧或解码跟不上，记录到播放错误历史并按坏文件跳过；处于缓冲状态时放宽到 30 秒，避免误伤慢速外置盘。暂停、拖动进度与打开期间不计时。

新视频在打开收尾阶段（启动播放、写入会话时）就播放结束，结束事件不再丢弃；只按媒体身份过滤旧视频的事件。自动播完进入已预加载的下一条后，重置“已播完”标记，新视频的进度照常保存。

## 原生播放验收

运行以下命令生成 H.264、4K H.264 和 4K HEVC 的 30 秒样本，关键帧间隔 10 秒，再在 macOS release 模式执行：

```sh
python3 scripts/prepare_playback_smoke.py
flutter run -d macos --release -t build/playback-smoke/main.dart
```

生成器需要 FFmpeg 提供 libx264 与 libx265。入口将样本写入应用沙盒临时目录，验证第 7 秒恢复、非关键帧定位、从第 17 秒预加载、播放器交接、软解设置、过期进度以及完整 Feed 初始化、连续切换和暂停时修改解码设置。增加 `--dart-define=SOFTWARE_PRELOAD=true` 可在 macOS 验证后台软解、释放旧硬解后交接的策略；此验证不能代替 Android 真机。入口同时检查已预加载交接复用原播放器且不显示加载提示。结束后清理样本和内存数据库。生成文件由 `.gitignore` 的 `/build/` 规则忽略。此入口只用于验收；交付前重新运行 `flutter build macos --release`，恢复正常应用入口。

样本使用纯色画面，适合验证解码路径、定位和状态，不用于推算真实视频的 CPU、功耗或平均帧率。高码率、HDR、损坏容器、外置盘断开、长时间连续播放与其他平台真机验收仍见 [TODO](../TODO.md)。本机 API 37 模拟器此前出现 EGL_BAD_ATTRIBUTE，不能作为 Android 原生画面验收。硬解选择参照 [mpv 手册](https://mpv.io/manual/stable/#options-hwdec)。

## 滑动方向与画面交接

下方放下一条，上方放上一条。滚轮向下浏览下一条、向上浏览上一条；拖动时向上拉当前画面，露出下方的下一条，向下拉则回到上方的上一条。触控板的小幅滚动累积到 20 像素后触发，反向滚动可以立即返回；同方向仍保留 350 ms 间隔，交接期间不重复切换。没有上一条时只轻拉当前页并回弹，不执行离场和打开操作；只有一条媒体或到达非循环队列末尾时，下一条也按边界回弹处理。初始化加载期间不接受滑动。

离场动画结束后，旧画面留在屏幕外。播放器就绪时更新已打开媒体 ID，新画面和零偏移在同一次构建中出现；等待异步交接时不把旧画面移回原位。打开期间忽略旧播放器的进度、播放结束等事件，避免额外跳过一条。返回未缓存的视频时，也不先等待无关的下一条预加载。

队列在内存中保留上一轮顺序。跨过循环边界后可以回到刚播过的最后一条，再向前时沿用原来的下一轮顺序。最多保留上一轮和下一轮各一份列表，播放器数量保持两个，不新增数据库历史。重扫、重建队列、切换范围和手动洗牌清除历史；更早的轮次和应用重启后的历史不保留。

以下入口用红、绿、蓝视频检查实际 Feed 画面：

```sh
python3 scripts/prepare_playback_smoke.py
flutter run -d macos --release -t build/playback-smoke/transition.dart
```

入口启用自动播放，发送滚轮和 macOS 触控板 pan/zoom 事件，读取 Feed 渲染截图的中心像素，检查首页边界回弹、首次向前、返回、跨轮返回时的目标颜色，以及旧画面离场后是否再次出现。结束后清理样本与临时数据库。截图采样不覆盖每个显示帧；交付前运行正常入口的 `flutter build macos --release`。

连续切换压力入口使用三秒短片（部分音轨长于画面）、接近结尾的保存进度，以及截断和中段写入噪声的损坏样本，随机滚轮切换并检查画面不停住：

```sh
python3 scripts/prepare_playback_smoke.py
flutter run -d macos --release -t build/playback-smoke/stress.dart --dart-define=ROUNDS=180
```

截图依赖窗口出帧；窗口被遮挡时 macOS 可能暂停绘制，入口会报“截图卡住”，这不代表播放队列卡住。

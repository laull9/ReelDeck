# 后续版本实施约定

DESIGN 中的 V1.1、V1.2 对应本次的第二、第三版。保留 Feed、目录、设置三处入口，默认仍只播放视频、使用纯随机。

## 播放与队列

范围增加子目录，身份仍使用 SourceId 和相对路径。时间排序采用文件修改时间，时间相同按相对路径排序。智能随机先洗牌，再按来源与父目录交错，单轮每个文件只出现一次；它不承诺均匀随机。

恢复会话保留队列。扫描更新只调整未播放部分，移除项目不应把索引跳到已播放项。模式切换会开启新一轮。循环时可选择保留顺序或重新洗牌。

图片与 GIF 由 Flutter 解码，按设置的停留时间推进，可暂停、拖动计时进度。视频继续交给 media_kit。只在当前图片播放时读取文件，不生成缩略图，不做媒体探测。图片读取限制为 64 MiB，过大的文件走错误恢复。关闭图片选项后仍保留索引和收藏记录。

## 文件操作

桌面通过原生桥接定位文件、移入系统回收站。确认框明确展示文件名。成功后再移除索引；失败保留文件与记录。Android SAF 没有统一的系统回收站接口，因此显示灰色入口和说明，禁止把永久删除伪装成回收站。

## 显示

精简模式提供完整控制、仅进度、无浮层三种状态。无浮层时，点击先唤出控制，再自动收起；快捷键和滑动继续工作。窄屏控制换行。动画、双击收藏、键盘控制和预加载都有持久化开关。

## 构建

固定 Flutter 3.47.5。Windows、macOS、Linux 分别产出 x64 与 arm64，Linux 同时生成 deb、rpm；Android 分拆 arm64-v8a、armeabi-v7a APK。每个任务检查二进制架构和包内容，全部成功后才进入 Release。普通分支与 PR 运行分析和测试，手动构建默认只保存 artifacts。

Windows ARM64 必须配套 ARM64 libmpv、ANGLE 和插件，不能混入 x64 DLL。Linux 依赖系统 libmpv，并在安装包声明依赖。Android 正式发布签名使用仓库 secrets；未配置时只产出标明测试签名的 APK。

## 容量与验收

媒体索引按授权目录保留，扫描替换失效项；移除目录清理相关状态。会话只保留一条；错误历史保留最近 100 条。设置写入串行化。播放器最多两个，图片只保留当前项。

功能测试覆盖范围边界、排序、智能随机、扫描更新、图片计时、文件操作失败、会话恢复和显示设置。各平台原生解码、可移动卷、SAF 权限和安装体验需要设备验收，CI 构建不能代替这些检查。
